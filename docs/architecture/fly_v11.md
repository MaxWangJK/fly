# Fly Polish V11 实现说明

## 原则

保留现有 Riverpod / Repository / Drift 架构、主题、文件仓储、离线授权与所有业务模块；不引入新的依赖，不生成 CRM 跟进任务。

## 数据库 14 → 15

- `customer_follow_ups` 增加 `origin`（旧记录默认 manual）、`quick_action_date`、`quick_snapshot`。
- 快捷操作快照保存上次/下次跟进日期、原跟进记录 ID 和版本、客户版本。事务内创建或撤销，仅软删除当日 quickTodayToggle。
- 后续新增跟进、修改跟进、编辑客户、改变下次日期等导致快照不再安全时，拒绝自动撤销，提示用户到跟进记录处理。
- `tags.scope` 加入 customer/order/note/task 命名空间，唯一键从 name 改为 scope+name。Files 已有独立 file_tags，不重复迁移。
- 历史原客户 ID 保留；订单、笔记、任务每个实际引用克隆到本域新 ID，并更新本域关联。只用于其他域的旧定义转 legacy，不再进入客户选择器。客户级别标签保持原 ID。
- 迁移在事务内执行，并检查外键；不会删库。旧版程序不支持升级后的 schema，应通过完整备份回退，不能直接拿旧程序打开升级后的数据库。

## 界面与业务

- Calendar 使用单日投影：进行中跨日→今天，未来→开始日，逾期→截止日，完成→completedAt；历史异常完成记录没有 completedAt 时退回 updatedAt。
- Today 保留原区间语义，未完成已过期项单独排序。不要把日历投影用作 Today 筛选。
- 月/周共享投影；周一至周日，日期格独立滚动；日期变化由现有 localTodayProvider 刷新。
- Calendar 采用 FlyColorScheme；空白滚轮不再切换月份，避免与格内滚动冲突。
- Review 沿用 q1–q9 JSON 和自动保存，不迁移回答；q1–q8 四个色块，q9 为全宽今日总结，日期选择上限今天。
- 文件只展示本身标签及可点击客户/订单关系，不复制客户业务标签。原有客户标签筛选仍查询真实客户关系。
- 标签搜索按所属域区分结果，跨域同名标签不共用记录。选择一个域的标签，仅显示该域关系。
- 笔记 Enter 拆分块，Shift+Enter 换行，空 checklist 退出为正文；标题后新块为正文。保留旧 Quote/Code 数据，但不提供新建入口。
- toolsVisible 存入现有导航设置；隐藏仅影响入口，沿用统一路由重定向，不删除装柜数据。
- 装柜待装组拖回时，在最近分节尝试底部左/中/右及合法堆叠位置；仅移动本组。找不到合法位置时保留既有碰撞回退或超限确认流程。
- 新剖面编辑器读取实际 scene groups，拖动 Y/Z 修改同一个控制器，继承撤销重做与保存。X 不由剖面修改。超出边界按真实尺寸绘制。

## 验证边界

依用户指示不运行 flutter analyze、flutter test、自动 UI 回归，也不启动应用或操作用户数据库。构建通过不是运行时/迁移/外部拖放验收通过，详见人工清单。
