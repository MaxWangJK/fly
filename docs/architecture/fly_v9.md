# Fly V9 — Files / Notes

## 范围与当前实现依据

基于 V8 的 Riverpod 2、GoRouter、Drift schema 10、统一 attachments 仓库及现有 Theme。保留业务模块，禁止清库；分阶段实现，每阶段验证。本文是设计与执行记录，不代表下列功能已全部验收。

## 文件

- `attachments` 为文件元数据唯一事实来源。增量增加 folderId、displayName、sha256、thumbnailRelativePath、lastOpenedAt；ManagedFile 是它的领域映射，而非第二份客户附件记录。
- 普通文件使用 library owner；客户附件仍为 customer owner，客户标签通过客户关系实时查询，与独立 FileTags / FileTagLinks 区分。
- FileFolder 使用 UUID 和 parentId；箭头展开，名称选择。默认直属文件，包含子文件夹为显式筛选。移动禁止形成环；删除子树时使用统一删除批次以便恢复时不复活先前已删除记录。
- Files 页面只有树与浏览器，不增加额外详情栏。网格默认、列表可切换；详细信息轻量弹层。
- 物理文件放 `files/<folderId or inbox>/<uuid>/<original-safe-name>`，UI 改名/移动不依赖物理树；所有路径相对 FlyData。
- 文件夹“在资源管理器中打开”显示当前直属文件选择器，再定位所选原件。逻辑移动不假装改变物理目录；空目录说明尚无直属文件，不创建误导性的空磁盘镜像。外部定位仅通过平台适配器执行。
- 文件夹软删除后清理该子树文件的缩略图，不删除原件；缓存清理失败明确提示，元数据删除仍可恢复。回收站不生成缩略图、不提供双击打开。
- 导入先流式复制到临时文件，同时计算摘要、报告进度；取消清理本次临时文件。提交成功才写元数据；重复不静默覆盖。替换保留可恢复的旧版本，不能影响业务附件。
- 图片按尺寸缓存缩略图；视频/PDF 在没有安全解码器时用类型图标与系统打开，不假装支持首帧预览。

## 笔记

NoteFolder 独立树，Note 独立实体；NoteBlock 持久化 typed contentJson，不把客户备注当笔记。包含段落、三级标题、列表、Checklist、引用、分割线、图片、附件、表格、代码。快捷输入只在当前块前缀匹配时转换；粘贴大段文本不触发意外转换。

编辑采用稳定块 ID、显式排序，保存状态可见，错误保留编辑内容；拖动排序与内容更新事务化。图片/文件使用统一附件 ID。未知块类型保留原 JSON，禁止静默丢弃。

草稿恢复：使用已有 AppSettings 的 `noteDraft:<noteId>` 持久化完整 JSON 草稿及基准修订号，无新增迁移。主记录保存成功后只清除与已保存内容匹配的草稿，避免旧保存删除新输入。重启时恢复未保存草稿；修订冲突提供“另存为新笔记”，不覆盖原文。正常关闭通过 Windows 生命周期通道等待保存；如最新草稿未成功落盘则阻止关闭。强制结束和断电不属于正常关闭保证。

笔记列表摘要读取前 3 块文字或媒体说明，合并空白并截取 160 个 Unicode 码点。只为列表可见行建立可自动释放的订阅，正文变化实时更新；摘要不作为额外持久化真相。

## 导航 / 搜索

新增 Files、Notes 在 Matrix 与 Tools 之间，固定可见；CRM 关闭时隐藏客户文件入口，当前客户文件页回 Files 最近，不删除数据。Global Search 文件结果带定位 ID；独立笔记结果不复用原有“客户备注”类型。

## 迁移与验证

Schema 11 仅追加表和字段，旧附件 displayName 回填 originalName。新增索引覆盖父目录、文件夹、软删除与更新时间。迁移测试要保留客户、订单、任务、装柜方案与原附件。

验收分层：领域/存储测试 → 仓库/迁移 → Files UI → Notes Editor → 原生拖出/剪贴板 → 搜索/备份 → 回归/Release。Windows 外部程序接受文件须分别实测，不用 Flutter 内部拖拽测试替代。
