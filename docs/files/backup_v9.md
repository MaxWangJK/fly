# V9 大文件备份决策

现状：FlyBackupService 将业务目录完整复制到暂存区再打包。不能直接把新增 files 目录无条件纳入每日 ZIP，否则大型视频重复复制。

目标：数据库及原有业务附件继续完整备份；托管库 files 使用备份位置中的不可变 blob 集合和每份快照 manifest。按摘要/大小确认已备份内容，只复制新增对象；manifest 包含 fileId、relativePath、摘要、大小。cache/thumbnails 可重建，不备份。

不可仅排除 files 然后把 ZIP 宣称完整备份。启用文件模块前必须实现：备份清单生成、流式对象写入、restore 缺失对象与摘要检查、还原到暂存区后整体切换，以及旧版 ZIP 恢复兼容。

备份清理先仅清理旧 manifest/ZIP，不自动回收 blob，避免删掉仍被其它快照引用的文件。后续对象 GC 需要扫描全部保留快照后单独实现。用户搬移备份时必须一起移动 ZIP/manifest 和 blob 集合。

恢复旧备份时不能把当前未备份的库文件静默覆盖或丢弃；在恢复前备份和风险确认中明确版本与文件范围。本文件为实施约束，不能替代恢复测试。
