# Windows 文件拖出（V11）

## 实现

- 保留既有 `fly/file_transfer` 平台通道和 Windows Shell IDataObject，不新增依赖。
- Windows Shell `BHID_DataObject` 提供本地文件数据对象，供支持标准 Shell/CF_HDROP 文件拖放的接收程序使用；`DoDragDrop` 只声明 COPY，不移动 FlyData 原件。
- V11 将原来仅角落拖动图标的入口扩展到文件卡片：按住并移动触发原生拖出。单击仍选择、双击仍系统打开、右键菜单保留。
- 库内移动：长按卡片后拖到 Fly 文件夹（LongPressDraggable）；普通拖动用于拖到外部。角落拖出入口继续保留。
- Ctrl+C/复制文件沿用 OLE Clipboard；复制路径是另一个独立操作，不伪装成复制文件。
- 不支持标准文件拖放的目标、以不同管理员权限运行的目标，可能拒绝拖入；不绕过 Windows 权限隔离。

## 人工验收（未代替用户执行）

1. 从普通文件夹和客户文件中分别选一个 PDF、中文名称图片。
2. 从图标/名称拖到资源管理器目录、桌面，确认生成副本、可以打开、FlyData 原件仍在。
3. 拖到微信和 WhatsApp Desktop 的聊天输入区域，确认作为附件接收；不要误发真实业务文件。
4. 拖动时按 Esc，确认取消且没有丢失文件。
5. 单击和双击不应触发拖出；长按内部拖到文件夹后，确认分类改变而没有重复导入。
6. Ctrl+C 后去资源管理器 Ctrl+V；再单独确认“复制文件路径”。

本轮遵照用户要求未启动应用或实际操作外部程序，因此目标应用兼容性尚待人工确认。
