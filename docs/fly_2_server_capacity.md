# Fly 2.0 服务器地址、监听与容量参考

## 地址

以下写法均支持，并归一化保存：

| 输入 | 实际 API 地址 |
| --- | --- |
| `198.51.100.10:8080` | `http://198.51.100.10:8080/api` |
| `http://198.51.100.10:8080` | `http://198.51.100.10:8080/api` |
| `https://198.51.100.10:8443` | `https://198.51.100.10:8443/api` |
| `http://sync.example.com` | `http://sync.example.com/api` |
| `https://sync.example.com` | `https://sync.example.com/api` |
| `https://sync.example.com/fly/api/` | `https://sync.example.com/fly/api` |
| `http://[2001:db8::1]:8080` | `http://[2001:db8::1]:8080/api` |

示例 IP 和域名仅为文档用途。省略协议固定使用 HTTP，不自动猜测或降级 HTTPS。默认官方地址仍为 `https://world-workshop.cn/api`。HTTP 没有传输加密；HTTPS 必须有设备信任且匹配域名/IP 的证书。切换不同服务器地址仍受一个本地目录绑定一个工作区的现有保护限制。

HTTP 使用 ws，HTTPS 使用 wss；分别显式采用有效的 80/443 或自定义端口。IPv6 Socket 连接去除 URL 方括号；URL 输入保留方括号。HTTP/HTTPS 模板与命令见 `server/README.md`。公网 Docker、真实证书与 Apple 原生设备仍需实际环境验收。

## 是否一直监听

- 云服务器服务进程持续运行，接受 HTTP 请求和 WebSocket 连接；空闲连接不代表持续传输业务文件。
- 开启云同步且应用运行时，客户端保持 WebSocket 通知连接；服务端每 2 秒检查该连接所属账号的变更，每 30 秒发送空闲心跳。心跳不触发拉取；收到变更通知后才唤醒同步。
- 客户端另有每 20 秒的补查、本地修改 1 秒合并后提交、断线 15 秒重连和前台恢复同步。游标/outbox 负责补上断线期间的数据。
- JWT 到期、网络断开会触发重新认证和连接；关闭同步或退出应用会结束监听。手机进入系统后台或被系统停止时，不保证连接常驻，恢复后补齐。
- 纯 LAN 只在用户开启电脑 LAN 服务、且电脑应用运行时监听默认 8765。手机连接电脑，无需手机开放服务端口。不同网络通常采用云端或可互通的 VPN。

## 2 核、4 GB、6 Mbps、约 20 MB 文件

以下按云服务器常见的 **6 Mbps 出口带宽**计算，而非 6 MB/s。理论总出口约 0.75 MB/s。20 MB 单个文件最短约 `20 × 8 / 6 = 26.7` 秒；20 MiB 文件约 28 秒。

同一出口同时向 N 台设备各发送 20 MB，假设公平共享且没有其它流量：

| 同时下载设备 | 每台理论最短时间 |
| --- | --- |
| 1 | 约 27 秒 |
| 2 | 约 53 秒 |
| 5 | 约 2 分 13 秒 |
| 10 | 约 4 分 27 秒 |
| 50 | 约 22 分钟 |

这些是带宽计算下限，实际更慢；TCP/TLS、网络质量、其它流量、磁盘及应用负载均有影响。上传到服务器取决于用户上传和服务器入口带宽，不能仅凭出口 6 Mbps 推算。哈希去重减少服务器存储和重复上传，不会免除每台新设备的首次下载流量。

**规划目标，不是压测结论：**先按 50 台常在线、少量客户/订单/任务变动验收，再逐档测试到 100 台。文件下载先按 1–2 台同时进行安排。当前没有实际 2 核 4 GB PostgreSQL 环境的容量实测，不能宣称保证 100 台或承诺上限。50–100 台“空闲在线”不等于 50–100 台同时首次全量同步或传文件。

当前实现每个 WebSocket 每 2 秒执行设备校验和最新 seq 查询，即 N 台在线约 N/2 轮检查、N 次数据库查询/秒；100 台约 100 次查询/秒。无文件、无待发送修改时，20 秒补查通常含 pull 和 conflicts 两个 HTTP 请求，100 台约 10 个请求/秒。打开文件内容同步后还会检查本地哈希及服务器去重状态，请求与客户端磁盘负载更高。同账号的写入串行，首次大量数据、频繁冲突、数据库历史规模均会影响吞吐。

同一办公出口首次注册/登录仍受每 IP 每分钟 10 次限制，应错开；已登录设备的会话刷新不与密码登录共享 Nginx 限流。API 默认 1 worker，数据库同步查询与文件校验也是瓶颈；扩容不能只按设备连接数判断。

同一办公室可保持云端记录同步、关闭云文件内容、开启已配对 LAN 文件内容，让 20 MB 字节通过内网传输。当前没有自动根据实时带宽选择下载线路，也没有全局文件并发排队限制；若所有远程设备都启用云文件，会共享 6 Mbps。

## 真实容量验收

在独立测试数据/存储、实际 2 核 4 GB、同样 PostgreSQL、Nginx、磁盘和带宽下，分别测试 10/25/50/100 个设备、不同账号及同一账号：

1. 空闲在线 30 分钟，检查心跳、JWT 刷新和重连。
2. 少量业务修改与冲突、断网恢复，确认所有游标追上且队列清空。
3. 1/2/5/10 台各下载 20 MB，测实际带宽、完成时间及重试。
4. 首次大工作区分页、服务重启和设备撤销。

记录 CPU、进程/容器内存、数据库连接/慢查询、API 延迟、断连率、文件吞吐以及队列滞后。只有这些结果满足实际业务要求，才提高部署设备数。当前本机功能测试、35,000 条分页检查和 Windows 构建不能替代此容量验收。

部署行为参考：[Nginx WebSocket 空闲超时与心跳说明](https://nginx.org/en/docs/http/websocket.html)、[FastAPI 进程与内存说明](https://fastapi.tiangolo.com/deployment/concepts/)、[Docker Compose 的 COMPOSE_FILE 配置](https://docs.docker.com/compose/how-tos/environment-variables/envvars/)。上述设备目标来自本项目的验收规划，不是这些文档提供的硬件容量基准。
