# Fly 完整需求与产品交接文档

整理日期：2026-11-12。适用对象：项目所有者、新电脑上的开发者，以及继续开发的 ChatGPT / Codex。

本文件汇总本机可读取的相关对话、20 份历史需求附件（可迁移副本已按最新要求整理）、现有源码、测试及交付记录。它既说明软件应该如何工作，也明确当前实现、版本和未完成事项。不是从零重建项目的指令。

## 1. 项目是什么

Fly 是面向外贸业务员、个体经营者和小型外贸团队中的个人使用者的工作软件。把客户跟进、订单执行、任务安排、文件、个人笔记、复盘和装柜规划放在同一个本地优先工作区。

产品风格是简洁、舒适、高效的个人工作软件，不做传统 ERP 大后台，不用大量表单、复杂面板和装饰图表堆砌功能。参考 任务管理软件 的任务交互、Google 日历的移动体验、Windows Explorer / macOS Finder 的文件操作，以及 Notion 类笔记体验；形成 Fly 自己的设计，不复制名称、素材或页面。

最初以 Windows x64 为主，1.0 已冻结；2.0 增加账户、云端及电脑手机同步、Android 体验。macOS 和 iOS 是明确的后续平台方向，但尚未在真实 Apple 环境完成构建与验收。

### 1.2 状态用语

- **已有实现**：源码及现有报告能证明存在；不等于全部平台实机验收。
- **已有实现，待实机验收**：自动测试或局部原生编译通过，摄像头、系统分享、外部程序等仍需设备确认。
- **预留 / 待完成**：有代码边界或产品规划，但尚未交付完整功能。
- **建议 / 待确认**：讨论过发展方向，没有转化为确定开发任务。

## 2. 不可破坏的原则

| 编号 | 要求 |
| --- | --- |
| CORE-01 | 所有业务编辑先持久化到本机 SQLite。断网、服务器故障、VPN 断开时仍能进行本地工作，恢复连接后补同步。 |
| CORE-02 | 不以注册或网络作为普通本地业务功能的依赖。同步登录、产品付费授权是不同能力，不混在一起。 |
| CORE-03 | 保留已有客户、订单、任务、笔记、文件和装柜方案。增量迁移，不删库、不重新播种覆盖、不替换既有业务 ID。 |
| CORE-04 | 客户、订单、任务是独立领域；不能把客户或订单当作任务来存储。标签、提醒、优先级等可复用成熟机制。 |
| CORE-05 | 同一个任务在任务列表、日历和四象限中使用同一记录；同一附件通过统一托管文件机制复用，避免多份权威数据。 |
| CORE-06 | 隐藏导航入口只影响显示，不删除业务数据。重新显示模块时内容仍在。 |
| CORE-07 | 保留 1.0 的提交及发布基线；2.0 继续在独立分支。build 39/40 功能与正式签名配置随本次本地检查点保存；迁移带走隐藏 `.git` 及之后的修改，不重置、不清理、不切分支。私有密钥与发行包另行安全转移。 |
| CORE-08 | 默认不自动加入演示业务数据。演示数据只有首次启动明确勾选、且客户/订单/任务全为空时创建一次，日期动态生成。 |
| CORE-09 | 文件业务身份使用 fileId / folderId 和相对路径，不用 Windows 盘符或文件名作身份；同名不代表同一文件。 |
| CORE-10 | 先检查已有工程，再做局部修改。沿用架构和主题，不重复实现已有功能，不无关重构、不随意增加依赖。 |

CORE-11：文档、官网和新资料不得出现中国品牌名称；用功能类型说明历史参考。此规则覆盖早期指定品牌的官网、支付与宣传要求。历史摘录允许进行此类整理，并明确记录副本改变。

CORE-12（2026-10-16）：安卓正式备案使用实际发布签名 APK 的包名、公钥和证书 MD5。长期发布签名保存在私有目录，后续发布必须复用；不得回退测试签名或因迁移缺文件而重建。原测试包与正式签名不同，换装前先确认业务数据和实体文件已备份。iOS 备案需独立的真实 iOS 发布证书，不能使用安卓证书。见 [正式签名说明](../release/android_release_signing_20261016.md)。

CORE-13（迁移交付）：公开备案字段、公钥、证书和核验清单随 Git 存档；APK/Windows 安装包本体仍在忽略的 `dist/`。交接资料必须区分证书指纹与文件哈希、正式签名与商业正式发售、已验证与待实机验收。iOS 当前仅项目 Bundle ID `com.flyproduct.fly`，尚无真实发布证书、公钥或签名 SHA-1，不生成占位值用于备案。

## 4. 工作区与设计系统

### 4.1 桌面

DESIGN-01：使用一级图标导航、按领域变化的二级目录、列表和详情；扩展内容渐进展开。头像、搜索、设置之间留合理空间，不模仿 ERP 固定大表单。

DESIGN-02：Dashboard、CRM（客户和订单联动）、工具可以显隐并持久保存。初始 Dashboard 隐藏，CRM 显示；桌面通常进入客户今天，手机进入客户全部；CRM 隐藏时退到任务今天。已保存的个人配置不被覆盖。

DESIGN-03：浅色/深色和多套配色共用布局与业务行为。目录、列表、编辑区应有自然分层，不能整页使用同一颜色。使用低饱和强调色、统一间距/圆角、轻边框，避免过度阴影与颜色抢夺注意。

DESIGN-04：清朗商务采用浅色卡片、克制的数据层级；其 Dashboard 布局用于其他主题。薄荷云境和青霭雅灰等后续主题保留。设置的外观方案使用响应式预览卡片，不做越来越长的单列列表。

DESIGN-05：所有功能必须有可理解的空、加载、错误、选择、禁用状态。详情内容较长时自适应并可滚动；键盘与鼠标行为符合平台惯例。

### 4.2 手机

MOBILE-01：底部固定五个入口：**客户、订单、任务、文件、我的**。日历和四象限并入任务切换区，节省导航空间。

MOBILE-02：顶部移除 Fly 文本、设置图标和 Ctrl+K；同步操作始终可找到。设置、账户与同步配置放“我的”。

MOBILE-03：客户/订单为手机列表，点击从底部打开可滚动详情，关联客户和订单同样使用合适的详情入口；详情覆盖底部导航，横屏及键盘弹出后仍能操作。

MOBILE-04：隐藏桌面导入/导出/下载等操作以及重复的“今天需要联系”“全部订单”标题。客户呈现全部、今天、级别和标签；订单呈现标签筛选。

MOBILE-05：手机不展示工具和资料库；不能因此删除工具、知识包或个人笔记数据。当前手机没有个人笔记一级入口，后续移动笔记入口须另行确认。

MOBILE-06：390×844 竖屏及 844×390 横屏已有界面回归。实际设备权限、相机、外部程序与系统分享须实测；不能以 Windows 渲染代替 Android/iOS 验收。

MOBILE-07（2026-10-17）：安卓全屏延伸背景，按系统实际安全区域避开挖孔、刘海、长条摄像头和手势区，不按品牌硬编码高度。支持横屏侧边切口，系统栏图标随明暗主题调整；不强制把交互控件盖到摄像头下面。

MOBILE-08：右下角新增与搜索都为 56×56；竖屏距离内容底部 36，横屏保留 16；列表末尾留出滚动空间。文件页例外：只有新增浮动按钮，搜索始终放顶部。

MOBILE-09（2026-11-01 最新）：手机“我的”保留个人名字和头像入口，设置内新增“我的”分类，统一注册、登录和账号操作；覆盖此前隐藏账号入口的规则。

## 5. 任务 Tasks

| 编号 | 有效需求与边界 |
| --- | --- |
| TASK-01 | 清单与任务分离。支持收集箱、全部、今天、未来 7 天、已完成、最近删除，以及可创建/重命名的个人清单。默认名称采用 Fly 自己的命名，不照搬 任务管理软件。 |
| TASK-02 | 清单支持父子层级及创建/选择。手机在导航下方分行展示全部、收集箱及所有有效自定义清单，超出限定区域可纵向滚动，不靠横向滑动发现目录；同步到达后即时刷新，加载失败有重试。管理入口保留层级树，选中后显示简短祖先路径，不为缺失数据伪造同名目录。 |
| TASK-03 | 手机任务导航顺序为今天、清单、复盘、日历、四象限；去掉重复“今天”标题。 |
| TASK-04 | 桌面保留搜索/新建任务共用输入。手机右下角“＋”只填名称创建；选中清单时创建在该清单，全部/收集箱创建到收集箱，今天创建带当天日期。任务/客户/订单的放大镜位于“＋”上方，点击展开纯搜索；文件页改为顶部常驻搜索。搜索提交不创建内容。 |
| TASK-05 | 今天先显示今日任务，逾期在下方分组；支持单条/批量顺延到今天。普通右键保留删除，过期任务另保留顺延。 |
| TASK-06 | 当前按创建时间倒序，修改优先级、标题或完成不改变创建排序。相同时间有稳定次序，不用旧的手动 sortOrder 覆盖新规则。 |
| TASK-07 | 详情简洁，突出备注，避免重复大标题。Markdown 备注、标签、清单、子检查项、日期、优先级、提醒、重复和重要/紧急继续保留。 |
| TASK-08 | 优先级与重要/紧急是独立概念。选择采用紧凑单选、方块对号等统一视觉；重要/紧急不需要大块重复说明。 |
| TASK-09 | 日期支持快速选择及自定义开始/截止。跨日任务不能错误漏出今天或日历。已删除不参与正常投影，已完成按相应视图展示。 |
| TASK-10 | 重复、提醒继续复用现有规则，不重写一套日历数据。详情可调整，默认重复为从不。 |
| TASK-11 | 点击方框完成后有“任务已完成”、绿色对号、短暂彩屑效果和撤销；提示 4 秒后自动消失，连续完成替换上一条提示；尊重系统减少动画设置。 |
| TASK-12 | 删除先进入回收站，可恢复。完成、删除、改期在列表、日历、四象限与 Dashboard 一致更新，并进入本地同步队列。 |

## 6. 日历与四象限

CAL-01：桌面保持月/周等已验收能力，月份滚轮切换、日期定位、任务显示、主题取色和快速新建。点击日期通过弹框/任务编辑创建，不在日格内硬塞输入框。

CAL-02：手机只用周/月，默认周；有上一页/下一页、回到今天、日期/月选择及新建。周时间区域和日期列可滚动，月视图日期可进入对应周。参考 Google 日历交互，没有接入 Google 账户、外部日历或 CalDAV。

CAL-03：全天日期范围包含最后一天；定时任务跨日按实际时间重叠，结束在午夜不重复落入次日。重叠任务应可辨认和操作。

CAL-04：手机长按拖动任务改期。周视图按 15 分钟落点改变时间/日期；月视图改变日期并保留时刻。保留全天属性、多日跨度、完成状态和重复规则。

CAL-05：拖动至边缘可滚动时间/日期。任务遮住目标位置时仍可落点。保存前检查拖动期间是否发生了日期修改；改期后显示新日期和撤销，撤销不能覆盖后续日期变更。

CAL-06：全天区默认每一天一条任务和“+N”，支持展开/收起，展开过长限定高度内部滚动。保持时间区空间，横屏计数按钮不能被裁切。

MATRIX-01：四象限是任务的重要/紧急投影，不建立第二套任务；可完成、新建、查看、删除、顺延以及拖动改变象限。任务文字、创建时间与拖动操作对齐，时间用次要文字。

MATRIX-02：手机横屏/竖屏均可到达全部象限，长列表可滚动，不因窗口变窄而无法操作。

### 8.1 金额与币种

- 金额以整数最小货币单位存储，避免直接用浮点数作账务事实；汇率以整数精度字段存储，按已有两位小数规则参与计算。
- 支持原始 USD 与 RMB/CNY 金额；收款和成本保留自己的实际币种及历史记录。汇总不能直接把 USD 与 RMB 相加。
- 已收、未收、成本卡片按原始币种表达；预计利润统一 RMB。需要换算却缺汇率时提示缺信息，不擅自当作 0 或按 1:1。
- 当前完整计算以 `lib/features/orders/domain/order.dart` 为准；`docs/orders/simple_financial_currency.md` 是更早的简化阶段说明，不能据此去掉后来实现的汇率和 RMB 利润。
- 同币种示例：销售 20,000，工厂成本 14,000，内陆 500，港杂 300，其他 200，退税 1,500，则利润 6,500。混合币种时先正确换算到 RMB 再计算。

```text
预计利润 RMB = 销售额 RMB + 退税 RMB + 其他收入 RMB
              - 工厂成本 RMB - 成本条目 RMB
未收款（订单币种） = 订单销售额 - 已收款换算到订单币种的合计
利润率 = 预计利润 RMB / 销售额 RMB（销售为零时不计算）
```

### 10.1 各平台数据目录

- 桌面可选择专用 FlyData；业务文件不能写到 Program Files，也不能依赖源码目录。
- Android 首次请求所需存储权限，允许时建立共享存储 `fly`，通常 `/storage/emulated/0/fly`；拒绝首次权限可用应用 Documents/fly，软件仍可用，不强制用户选目录。
- 已有设备保留旧目录；已有共享目录权限被撤销时要求重新授权，不能偷偷切空目录造成丢数据错觉。
- iOS 使用应用 Documents/fly 并开启文件共享；受沙箱约束，不能承诺在整部手机文件系统根目录任意创建公共目录。
- macOS 具体目录与权限在 Mac 上验证，先使用数据副本，不把源码迁移与真实业务数据迁移混为一谈。

## 15. Fly 2.0 同步

### 15.1 连接方式与地址

SYNC-01（2026-11-01 当前）：手机和电脑设置提供本地同步/云同步；首次默认本地，之后记住所选方式和启用状态。LAN 同步业务记录与实体文件；云端同步记录及文件信息，不传任何用户的图片和文件内容。默认云 API 内部保持系统配置，用户界面不显示默认域名；自建地址仅在“我的”中设置，首次为空。同步页不显示云地址、邮箱或空间 ID。

SYNC-02（云地址）：官方地址 `world-workshop.cn/api` 内部使用 HTTPS；支持自建域名/IP、端口、HTTP/HTTPS、IPv6 和代理路径，无协议输入可尝试适用协议。显式 HTTPS 验证证书，不为错误证书悄悄降级。保留已有后端、账户身份及工作区上下文；邮箱注册登录已按 AUTH-01 开发。

SYNC-03：电脑默认开启本地服务并显示配对二维码；手机扫描，不手工输入地址，直接提示配对成功/失败。电脑作为 Host，手机主动连接，不把 iOS 手机当常驻服务器。已配对电脑可以验证设备秘密后通过局域网发现新地址；保留二维码作为首次信任与网络不支持发现时的入口。

SYNC-04：当前手机直连通过 LAN HTTP 数据/文件接口，前台约 2 秒补查，本机编辑约 250 ms 合并发送；云端使用 WebSocket 通知 + HTTP 增量传输、每 5 分钟补查。已启用账号启动和恢复前台立即同步；同步中再次修改或收到提醒保留后续轮次。通知断线按 2–60 秒退避重连；手机后台断开，回前台重连。传输期间仍调度增量记录，文件 I/O 不占用主机的业务事务队列；文件并发有界，同一上传按内容身份串行。没有把纯 LAN 实现成常驻 WebSocket 或公网穿透。

SYNC-05：早期要求电脑→手机、手机→电脑、双向方向；协议/主机保留方向能力，现用户模式自动双向，不应误把历史方向 enum 删除或重新暴露多套混乱开关。

SYNC-14：客户端与服务端均默认禁止云文件内容传输，没有特殊邮箱例外。后端保留旧文件接口用于兼容/隔离测试，当前云部署固定关闭该能力。

SYNC-15：SHA-256 内容身份、用户内去重、分片续传、`.part` 校验后原子落盘。旧缺哈希记录可补齐；本地外部修改检测后更新元数据。不同文件取并集，同 fileId 二进制冲突保留副本。

实现范围（2026-11-01）：上传保留分片续传；下载新增 Range、强 ETag/If-Range、内容身份绑定的 `.part` 与侧车文件，中断/重启保留偏移，完成验证长度与 SHA-256，服务器忽略 Range 时安全重新下载。永久删除清理临时文件及侧车。LAN 链路当前仍为 HTTP，令牌鉴权不代表已加密；本轮未引入 LocalSend 或实现 LAN TLS。

SYNC-16：云/LAN下载不依赖另一设备的绝对 Windows 路径；元数据到了但内容源还没上传时等源，不阻断其他文件。手机选择器/相机照片先持久化，再上传。

场景、自动规则与 Ubuntu 现有网站接入见 [本轮记录](../release/sync_multi_device_20261101.md) 和 [部署说明](../../server/deploy/cloud_sync_20261101.md)。自动合并不能推断错误设备时钟的真实先后，采用可复现规则并保留候选审计；并非识别同名对象或语义理解。

### 15.6 后端部署与容量

BACKEND-01（2026-11-01 最新）：后端位于 `server/`，与主工程同目录树；Python/FastAPI、SQLAlchemy、Alembic、PostgreSQL。Ubuntu 24.04 默认采用系统 PostgreSQL（16 系列）单独安装，Python 虚拟环境与 systemd 独立运行，保留现有 Nginx/PHP 和 HTTPS。不依赖 Docker；原容器部署保留可选，Redis 不是当前必需。

BACKEND-05：因用户服务器无法下载 Docker，提供简单原生部署流程、隐藏输入数据库密码的配置工具和一条命令安装脚本；保留现有数据库/配置/JWT，自动增量迁移、开机自启及失败重启。后台仍只绑定 `127.0.0.1:18766`，Nginx 路由不变。参见 [原生部署](../../server/deploy/ubuntu-native.md)。

BACKEND-02：用户隔离、设备撤销、JWT刷新、输入/大小/路径检查、幂等与原子事务；数据库和文件存储要备份和迁移。部署手册已有配置、TLS、健康、恢复、升级步骤。

BACKEND-03：参考机器为 2 核/4 GB、6 Mbps 出口、约 20 MB 文件。理论单次 20 MB 出口下限约 27 秒，20 MiB 约 28 秒；并发共享带宽，空闲在线数不等于同时传文件数。

BACKEND-04：50→100 台是分档压测目标，不是保证容量。实际 PostgreSQL、CPU、内存、磁盘、变更量、账号分布、首次同步和文件并发需实测。当前没有动态最优线路选择、全局文件并发调度或服务端历史压缩快照。

后端与官网是两个系统，不能把 `web/` 的 PHP 支付后台当作 `server/` 的同步 API。
