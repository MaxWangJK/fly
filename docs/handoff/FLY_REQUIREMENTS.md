# Fly 完整需求与产品交接文档

整理日期：2026-10-17。适用对象：项目所有者、新电脑上的开发者，以及继续开发的 ChatGPT / Codex。

本文件汇总本机可读取的相关对话、19 份历史需求附件（可迁移副本已按最新要求整理）、现有源码、测试及交付记录。它既说明软件应该如何工作，也明确当前实现、版本和未完成事项。不是从零重建项目的指令。

## 1. 项目是什么

Fly 是面向外贸业务员、个体经营者和小型外贸团队中的个人使用者的工作软件。把客户跟进、订单执行、任务安排、文件、个人笔记、复盘和装柜规划放在同一个本地优先工作区。

产品风格是简洁、舒适、高效的个人工作软件，不做传统 ERP 大后台，不用大量表单、复杂面板和装饰图表堆砌功能。参考 任务管理软件 的任务交互、Google 日历的移动体验、Windows Explorer / macOS Finder 的文件操作，以及 Notion 类笔记体验；形成 Fly 自己的设计，不复制名称、素材或页面。

最初以 Windows x64 为主，1.0 已冻结；2.0 增加账户、云端及电脑手机同步、Android 体验。macOS 和 iOS 是明确的后续平台方向，但尚未在真实 Apple 环境完成构建与验收。

### 1.2 状态用语

- **已有实现**：源码及现有报告能证明存在；不等于全部平台实机验收。
- **已有实现，待实机验收**：自动测试或局部原生编译通过，摄像头、系统分享、外部程序等仍需设备确认。
- **预留 / 待完成**：有代码边界或产品规划，但尚未交付完整功能。
- **建议 / 待确认**：讨论过发展方向，没有转化为确定开发任务。

## 2. 不可破坏的原则

| 编号 | 要求 |
| --- | --- |
| CORE-01 | 所有业务编辑先持久化到本机 SQLite。断网、服务器故障、VPN 断开时仍能进行本地工作，恢复连接后补同步。 |
| CORE-02 | 不以注册或网络作为普通本地业务功能的依赖。同步登录、产品付费授权是不同能力，不混在一起。 |
| CORE-03 | 保留已有客户、订单、任务、笔记、文件和装柜方案。增量迁移，不删库、不重新播种覆盖、不替换既有业务 ID。 |
| CORE-04 | 客户、订单、任务是独立领域；不能把客户或订单当作任务来存储。标签、提醒、优先级等可复用成熟机制。 |
| CORE-05 | 同一个任务在任务列表、日历和四象限中使用同一记录；同一附件通过统一托管文件机制复用，避免多份权威数据。 |
| CORE-06 | 隐藏导航入口只影响显示，不删除业务数据。重新显示模块时内容仍在。 |
| CORE-07 | 保留 1.0 的提交及发布基线；2.0 继续在独立分支。build 39/40 功能与正式签名配置随本次本地检查点保存；迁移带走隐藏 `.git` 及之后的修改，不重置、不清理、不切分支。私有密钥与发行包另行安全转移。 |
| CORE-08 | 默认不自动加入演示业务数据。演示数据只有首次启动明确勾选、且客户/订单/任务全为空时创建一次，日期动态生成。 |
| CORE-09 | 文件业务身份使用 fileId / folderId 和相对路径，不用 Windows 盘符或文件名作身份；同名不代表同一文件。 |
| CORE-10 | 先检查已有工程，再做局部修改。沿用架构和主题，不重复实现已有功能，不无关重构、不随意增加依赖。 |

CORE-11：文档、官网和新资料不得出现中国品牌名称；用功能类型说明历史参考。此规则覆盖早期指定品牌的官网、支付与宣传要求。历史摘录允许进行此类整理，并明确记录副本改变。

CORE-12（2026-10-16）：安卓正式备案使用实际发布签名 APK 的包名、公钥和证书 MD5。长期发布签名保存在私有目录，后续发布必须复用；不得回退测试签名或因迁移缺文件而重建。原测试包与正式签名不同，换装前先确认业务数据和实体文件已备份。iOS 备案需独立的真实 iOS 发布证书，不能使用安卓证书。见 [正式签名说明](../release/android_release_signing_20261016.md)。

CORE-13（迁移交付）：公开备案字段、公钥、证书和核验清单随 Git 存档；APK/Windows 安装包本体仍在忽略的 `dist/`。交接资料必须区分证书指纹与文件哈希、正式签名与商业正式发售、已验证与待实机验收。iOS 当前仅项目 Bundle ID `com.flyproduct.fly`，尚无真实发布证书、公钥或签名 SHA-1，不生成占位值用于备案。

## 4. 工作区与设计系统

### 4.1 桌面

DESIGN-01：使用一级图标导航、按领域变化的二级目录、列表和详情；扩展内容渐进展开。头像、搜索、设置之间留合理空间，不模仿 ERP 固定大表单。

DESIGN-02：Dashboard、CRM（客户和订单联动）、工具可以显隐并持久保存。初始 Dashboard 隐藏，CRM 显示；桌面通常进入客户今天，手机进入客户全部；CRM 隐藏时退到任务今天。已保存的个人配置不被覆盖。

DESIGN-03：浅色/深色和多套配色共用布局与业务行为。目录、列表、编辑区应有自然分层，不能整页使用同一颜色。使用低饱和强调色、统一间距/圆角、轻边框，避免过度阴影与颜色抢夺注意。

DESIGN-04：清朗商务采用浅色卡片、克制的数据层级；其 Dashboard 布局用于其他主题。薄荷云境和青霭雅灰等后续主题保留。设置的外观方案使用响应式预览卡片，不做越来越长的单列列表。

DESIGN-05：所有功能必须有可理解的空、加载、错误、选择、禁用状态。详情内容较长时自适应并可滚动；键盘与鼠标行为符合平台惯例。

### 4.2 手机

MOBILE-01：底部固定五个入口：**客户、订单、任务、文件、我的**。日历和四象限并入任务切换区，节省导航空间。

MOBILE-02：顶部移除 Fly 文本、设置图标和 Ctrl+K；同步操作始终可找到。设置、账户与同步配置放“我的”。

MOBILE-03：客户/订单为手机列表，点击从底部打开可滚动详情，关联客户和订单同样使用合适的详情入口；详情覆盖底部导航，横屏及键盘弹出后仍能操作。

MOBILE-04：隐藏桌面导入/导出/下载等操作以及重复的“今天需要联系”“全部订单”标题。客户呈现全部、今天、级别和标签；订单呈现标签筛选。

MOBILE-05：手机不展示工具和资料库；不能因此删除工具、知识包或个人笔记数据。当前手机没有个人笔记一级入口，后续移动笔记入口须另行确认。

MOBILE-06：390×844 竖屏及 844×390 横屏已有界面回归。实际设备权限、相机、外部程序与系统分享须实测；不能以 Windows 渲染代替 Android/iOS 验收。

MOBILE-07（2026-10-17）：安卓全屏延伸背景，按系统实际安全区域避开挖孔、刘海、长条摄像头和手势区，不按品牌硬编码高度。支持横屏侧边切口，系统栏图标随明暗主题调整；不强制把交互控件盖到摄像头下面。

MOBILE-08：右下角新增与搜索都为 56×56；竖屏距离内容底部 36，横屏保留 16；列表末尾留出滚动空间。文件页例外：只有新增浮动按钮，搜索始终放顶部。

MOBILE-09（2026-10-17）：手机“我的”移除账户设置功能入口，保留常规设置与电脑同步设置；现有账户身份和业务数据不因隐藏入口而删除。

## 5. 任务 Tasks

| 编号 | 有效需求与边界 |
| --- | --- |
| TASK-01 | 清单与任务分离。支持收集箱、全部、今天、未来 7 天、已完成、最近删除，以及可创建/重命名的个人清单。默认名称采用 Fly 自己的命名，不照搬 任务管理软件。 |
| TASK-02 | 清单支持父子层级及创建/选择。手机在导航下方分行展示全部、收集箱及所有有效自定义清单，超出限定区域可纵向滚动，不靠横向滑动发现目录；同步到达后即时刷新，加载失败有重试。管理入口保留层级树，选中后显示简短祖先路径，不为缺失数据伪造同名目录。 |
| TASK-03 | 手机任务导航顺序为今天、清单、复盘、日历、四象限；去掉重复“今天”标题。 |

| TASK-05 | 今天先显示今日任务，逾期在下方分组；支持单条/批量顺延到今天。普通右键保留删除，过期任务另保留顺延。 |
| TASK-06 | 当前按创建时间倒序，修改优先级、标题或完成不改变创建排序。相同时间有稳定次序，不用旧的手动 sortOrder 覆盖新规则。 |
| TASK-07 | 详情简洁，突出备注，避免重复大标题。Markdown 备注、标签、清单、子检查项、日期、优先级、提醒、重复和重要/紧急继续保留。 |
| TASK-08 | 优先级与重要/紧急是独立概念。选择采用紧凑单选、方块对号等统一视觉；重要/紧急不需要大块重复说明。 |
| TASK-09 | 日期支持快速选择及自定义开始/截止。跨日任务不能错误漏出今天或日历。已删除不参与正常投影，已完成按相应视图展示。 |
| TASK-10 | 重复、提醒继续复用现有规则，不重写一套日历数据。详情可调整，默认重复为从不。 |
| TASK-11 | 点击方框完成后有“任务已完成”、绿色对号、短暂彩屑效果和撤销；提示 4 秒后自动消失，连续完成替换上一条提示；尊重系统减少动画设置。 |
| TASK-12 | 删除先进入回收站，可恢复。完成、删除、改期在列表、日历、四象限与 Dashboard 一致更新，并进入本地同步队列。 |

## 6. 日历与四象限

CAL-01：桌面保持月/周等已验收能力，月份滚轮切换、日期定位、任务显示、主题取色和快速新建。点击日期通过弹框/任务编辑创建，不在日格内硬塞输入框。

CAL-02：手机只用周/月，默认周；有上一页/下一页、回到今天、日期/月选择及新建。周时间区域和日期列可滚动，月视图日期可进入对应周。参考 Google 日历交互，没有接入 Google 账户、外部日历或 CalDAV。

CAL-03：全天日期范围包含最后一天；定时任务跨日按实际时间重叠，结束在午夜不重复落入次日。重叠任务应可辨认和操作。

CAL-04：手机长按拖动任务改期。周视图按 15 分钟落点改变时间/日期；月视图改变日期并保留时刻。保留全天属性、多日跨度、完成状态和重复规则。

CAL-05：拖动至边缘可滚动时间/日期。任务遮住目标位置时仍可落点。保存前检查拖动期间是否发生了日期修改；改期后显示新日期和撤销，撤销不能覆盖后续日期变更。

CAL-06：全天区默认每一天一条任务和“+N”，支持展开/收起，展开过长限定高度内部滚动。保持时间区空间，横屏计数按钮不能被裁切。

MATRIX-01：四象限是任务的重要/紧急投影，不建立第二套任务；可完成、新建、查看、删除、顺延以及拖动改变象限。任务文字、创建时间与拖动操作对齐，时间用次要文字。

MATRIX-02：手机横屏/竖屏均可到达全部象限，长列表可滚动，不因窗口变窄而无法操作。

## 7. 客户 CRM

CRM-01：客户至少关联级别/分类、状态、来源、多联系人、跟进记录、备注、自定义字段、标签与订单。级别 A/B/C/D 是可管理实体，不是写死 enum；支持修改、排序及删除/停用的已有规则。

CRM-02：“今天”表示到期需要联系的客户；“未来/最近 7 天”指未来要跟进，不是历史创建时间。完成今天这一轮跟进不能把客户变为已完成或删除。

CRM-03：快捷勾选生成跟进记录、更新最近跟进、按重复规则更新下次跟进，并给出完成/撤销反馈。撤销不能覆盖之后的编辑。重复规则涵盖已有日/周/月/工作日与自定义能力，按日历月处理月末，不用固定 30 天替代月。

CRM-04：跟进内容与下一步可以独立提交，空白不产生垃圾记录；Enter 保存、Shift+Enter 换行适用于这些快捷输入。跟进历史可编辑/软删除，顶部下一步回退到最新有效记录。

CRM-05：下次行动可有类型和自由文本。客户备注是独立可查看/编辑的记录，长内容通过扩展详情处理，不挤在顶部。

CRM-06：客户级别与关联标签在事务内联动，但 Category 和 Tag 不能合成一个领域。选择 A 级可匹配 A 分类或明确的 A 标签；多标签采用 AND；选择全部清除筛选。

CRM-07：客户、订单、任务、笔记标签分作用域。停用保留历史关联，删除确认引用数量，安全清理孤儿标签，不误删受保护的分类标签和其他领域引用。

CRM-08：在当前客户级别下创建客户应进入该级别；客户名称做空格/大小写等规范化重复检测，不能悄悄覆盖。客户来源支持自由文本，基础信息可折叠，自定义字段保留。

CRM-09：桌面进入列表时自动展示第一条可见客户详情；手机点行打开底部详情。手机默认全部，新建后清理会隐藏新客户的搜索/标签状态。电脑同步来的无跟进日期客户也能进入全部列表。

CRM-10：客户详情能新建订单、查看该客户订单；订单点客户名返回正确客户。携带客户筛选和选中上下文，不混入别人的订单。

CRM-11：客户软删除时说明关联订单数量，不顺手删除订单。可恢复，历史跟进及附件保留既有关系。

CRM-12：桌面支持 Excel 模板、导入映射、预览、规范化重复判断、跳过/覆盖/新增、逐行失败原因，以及按当前筛选/全部导出；手机不显示这些桌面操作。

## 8. 订单、执行与财务

ORD-01：订单独立于任务，关联客户、状态、标签、重要/紧急、优先级、交期、备注、产品、工厂、生产条目、收款、成本及文件。

ORD-02：订单状态和标签可管理，标签停用不丢历史关系。侧栏主要标签按有效引用数排序，保持紧凑，不无限增加默认项；手机显示标签筛选而不显示冗余大标题/下载。

ORD-03：工厂、产品轻量实体，可选择和快速创建。生产条目记录产品、数量、工厂、成本、下单/生产进展；未给工厂下单须明显提醒，不因整单已进入生产状态而掩盖遗漏。不同工厂用可区分、低饱和标识。

ORD-04：默认保留订单既有紧急/重要/优先级排序，不把“任务创建倒序”未经确认套到 CRM 和订单。桌面默认展示首条订单，手机点行从底部打开。

### 8.1 金额与币种

- 金额以整数最小货币单位存储，避免直接用浮点数作账务事实；汇率以整数精度字段存储，按已有两位小数规则参与计算。
- 支持原始 USD 与 RMB/CNY 金额；收款和成本保留自己的实际币种及历史记录。汇总不能直接把 USD 与 RMB 相加。
- 已收、未收、成本卡片按原始币种表达；预计利润统一 RMB。需要换算却缺汇率时提示缺信息，不擅自当作 0 或按 1:1。
- 当前完整计算以 `lib/features/orders/domain/order.dart` 为准；`docs/orders/simple_financial_currency.md` 是更早的简化阶段说明，不能据此去掉后来实现的汇率和 RMB 利润。
- 同币种示例：销售 20,000，工厂成本 14,000，内陆 500，港杂 300，其他 200，退税 1,500，则利润 6,500。混合币种时先正确换算到 RMB 再计算。

```text
预计利润 RMB = 销售额 RMB + 退税 RMB + 其他收入 RMB
              - 工厂成本 RMB - 成本条目 RMB
未收款（订单币种） = 订单销售额 - 已收款换算到订单币种的合计
利润率 = 预计利润 RMB / 销售额 RMB（销售为零时不计算）
```

### 8.2 收款、成本和附件

ORD-05：收款采用多笔记录，而非单一 paidAmount：金额、币种、类型、日期及可选附件。类型可自由填写，支持定金/尾款快捷入口、编辑和软删除。

ORD-06：成本有工厂、内陆、港杂及其他条目和可选附件，支持方便的快捷录入及编辑。存在新成本条目时不能重复加入迁移前的旧成本字段。

ORD-07：收齐货款只给轻量状态建议，不自动替用户改订单状态；超收、部分收款仍应如实呈现。

ORD-08：订单文件可按 PI/CI/PL/CO、转账/收款等用途分类，可关联付款记录。上传、桌面拖入、打开系统程序、关系查看及确认删除保留；SQLite 只存元数据，不存整份二进制。

## 9. Dashboard、我的聚焦、今日复盘

DASH-01：Dashboard 初始隐藏，可在设置启用。采用五项指标、当前工作分布、明细和跨模块跳转：今天跟进客户、今天任务、待收款、紧急订单、本月利润等使用真实查询，不用装饰性假数字。

DASH-02：保留 build28 风格的工作分布，加入重要且紧急数量/摘要；页面精简，一眼理解，不重复摆放同一信息。其他配色沿用清朗商务的结构，仅换颜色。

FOCUS-01：“我的聚焦”位于任务模块、今日复盘下面；五项依次为我的座右铭、人生主线、本月重点、本周重点、今日提醒。点击编辑、保留历史，今日提醒按日期保存。

FOCUS-02：Return/Enter 换行；光标或鼠标离开编辑框时自动保存。编辑框和保存后的长内容自适应，不限制三行。不把这条规则套到专门设计为 Enter 快捷提交的跟进/新建任务输入。

REVIEW-01：复盘按日期保存，四组为今日事实、问题原因、经验、明日行动，底部为今日总结。明日最重要的三件事提供三个独立输入，原有内容迁移保留。

REVIEW-02：日期不能进入未来；默认今天。前一天优先去更早的最近一条已有记录，没有更早记录则去前一个自然日；可以用日历选择某个过去日期补写。今天的后一天不可点击。

REVIEW-03：历史/编辑按钮切换；历史按日期呈卡片/瀑布流，可滚动、拖动和点击回编辑。只展示已填字段，固定问题采用短标签，完整问题仍可查看。

REVIEW-04：卡片随内容改变宽高，一行可 2/3 张或更多；长内容不能造成极端比例，可适度截断后点击读全。主题分层自然，不整页同色；复盘占完整工作区，不留无用的“选择一个任务”面板。

REVIEW-05：收到手机同步的当前日期答案时，电脑当前页必须直接刷新显示内容，不需要切换历史记录。正在本机保存或保存失败的字段保留待保存内容；其他同步字段与清空答案正常更新。已有答案按下条卡片规则展示。

REVIEW-06（2026-10-17）：手机与电脑的今日复盘呈一张内容卡片。空答案仍可填写；已有答案失去焦点或点击完成后收起输入框，显示完整文字，点击内容再编辑。输入中自动保存不强制收起；保留多行、清空、同步刷新与保存失败重试，不能靠刷新页面丢弃未保存内容。

## 10. 文件管理

FILE-01：桌面为一级入口 + 文件夹树 + 浏览器，不不断增加第三/第四面板。包含最近、客户文件、我的文件、最近删除；客户文件包含业务附件智能集合，并按 FILE-18 支持在此入口新增普通资料，不把旧业务附件搬成普通文件。

FILE-02：文件夹可以多层，使用稳定 folderId。箭头展开/收起，名称选择；支持新建子目录、重命名、删除/恢复、位置查看和已有移动操作。默认直属文件，可选包含子目录。

FILE-03：路径导航、搜索、文件标签、客户标签筛选、修改/创建时间、名称、类型、大小排序。客户和订单关系可跳转，不默认在文件卡片塞满业务标签；文件标签与客户标签分开存储/查询。

FILE-04：手机文件夹内首次默认相册小图片，点击能看真实缩略图，可切列表。图片默认在前，可改文件在前，组内仍按所选顺序；视图、排序及多选入口集中在右上角三点菜单。电脑首次列表，保留三种视图。

FILE-05：手机保存视图、排序、图片优先和客户文件入口可见性，每次进入仍展示文件夹首页，不恢复到旧集合/文件夹或应用已隐藏的标签过滤。桌面继续保存集合/文件夹、标签和子目录等选项。两端偏好分开，不同步覆盖对方；失效引用安全回退。

FILE-06：点图片直接打开可缩放的图片查看器；Excel、PDF、Word 等直接调用系统默认程序，不新增内置 Office/PDF 预览依赖。缺少文件或外部查看器时原因清楚。

FILE-07：手机长按菜单含详情、重命名、分享、删除，并可进入选择。分享是实际文件的系统面板，由安装应用提供通讯应用、WhatsApp、信息、Facebook 等目标与联系人；没有自动调用这些平台账号 API，也不能承诺每个程序支持全部文件类型。

FILE-08：提供多选、全选、已选数量、批量分享、批量删除/永久删除、取消。全选只针对当前结果；位置/搜索/标签变更清空选择，避免操作隐藏文件。批量处理中有进度、防重复操作与部分失败反馈。

FILE-09：同名文件批量分享使用唯一副本名，显示名没有后缀时补原后缀。任一选中文件尚未下载/已删除应提示，不悄悄漏分享。无分享完成回调的平台保留临时副本供接收方读取，后续安全过期清理。

FILE-10：桌面导入支持文件选择、拖入、进度、取消及重复决定；手机支持文件/相册内容流和拍照上传。选择器的临时路径不可作为永久源，导入成功必须写 Fly 的持久托管目录。

FILE-11：Windows 支持原生拖出到 Explorer、桌面和接受标准文件拖放的软件，以及文件剪贴板复制/粘贴；与内部文件夹移动区分。实际第三方接收能力仍需验收，不能把 Windows 原生适配直接当作 macOS/iOS 能力。

FILE-12：普通删除进入最近删除，保留恢复；业务附件删除说明对所属记录的影响。永久删除是真实清理本机实体、分片、缩略图、Fly 分享副本和无其他引用的同步内容，同时保留同步删除记录防止旧设备复活。

FILE-13：永久删除传播到其他设备；离线设备下次同步再清理。同内容仍被其他文件引用时保留。已分享到外部应用、导出或备份的副本不由一次 Fly 删除自动抹除。

FILE-14：同步成功的文件记录不等于实体已下载；下载校验通过才确认可用。打开/分享缺失实体时给出等待同步提示，而不是普通“找不到文件”把元数据当作可读文件。

FILE-15（2026-10-17）：手机文件首页只展示“客户文件”和电脑端“我的文件”下的一级文件夹，例如 light、door、panel；不再展示桌面树、我的文件、标签筛选和子目录复选框。保留顶部搜索及右上角三点菜单。搜索可查文件及文件夹；进入目录后支持子目录、返回和系统返回键。

FILE-16：手机长按客户文件可移除本机入口，不删除客户、附件或文件夹，也不产生同步删除；三点菜单可恢复显示。真实普通文件夹的重命名/删除仍按原同步语义执行，并保留最近删除中的恢复入口。

FILE-17：原本直接位于“我的文件”根目录的散文件放到手机虚拟“未分类文件”入口，只有存在散文件时展示；不搬移实体或改业务归属，避免精简首页后旧导入文件不可达。

FILE-18（2026-10-17）：客户文件入口内也有“＋”，可导入、拍照和新建子目录。新建普通资料使用稳定同步根目录 `fly-customer-files`，电脑“我的文件”可访问；现有客户/订单附件不改归属。内部根目录不在手机首页重复展示，子目录返回客户文件入口。真实根目录被删除时须先恢复，不偷偷复活历史删除内容。

FILE-19：相册式文件夹网格以实际可用宽度计算，常见手机每排至少三项，小屏可两项，横屏/宽屏增加列数；保留列表切换、排序及本机偏好。

### 10.1 各平台数据目录

- 桌面可选择专用 FlyData；业务文件不能写到 Program Files，也不能依赖源码目录。
- Android 首次请求所需存储权限，允许时建立共享存储 `fly`，通常 `/storage/emulated/0/fly`；拒绝首次权限可用应用 Documents/fly，软件仍可用，不强制用户选目录。
- 已有设备保留旧目录；已有共享目录权限被撤销时要求重新授权，不能偷偷切空目录造成丢数据错觉。
- iOS 使用应用 Documents/fly 并开启文件共享；受沙箱约束，不能承诺在整部手机文件系统根目录任意创建公共目录。
- macOS 具体目录与权限在 Mac 上验证，先使用数据副本，不把源码迁移与真实业务数据迁移混为一谈。

### 15.5 后端部署与容量

BACKEND-01：后端位于 `server/`，与主工程同目录树；Python/FastAPI、SQLAlchemy、Alembic、PostgreSQL 16，Ubuntu 24.04 部署，Docker/Compose + Nginx HTTP/HTTPS。Redis 不是当前必需。

BACKEND-02：用户隔离、设备撤销、JWT刷新、输入/大小/路径检查、幂等与原子事务；数据库和文件存储要备份和迁移。部署手册已有配置、TLS、健康、恢复、升级步骤。

BACKEND-03：参考机器为 2 核/4 GB、6 Mbps 出口、约 20 MB 文件。理论单次 20 MB 出口下限约 27 秒，20 MiB 约 28 秒；并发共享带宽，空闲在线数不等于同时传文件数。

## 18. 验收与交接规则

1. 先确认 `.git`、当前分支、最新本地提交及以后新增的工作区改动均在，不切主分支，不清工作区。
2. 用隔离数据验证旧库迁移、客户订单关系、任务、笔记和实体文件完整；不能拿生产数据库作测试夹具。
3. 任务/日历/四象限同一记录；跨日、午夜、完成、软删除/恢复和拖动撤销正确。
4. 客户创建和电脑同步到手机后可见；客户与订单底部详情、标签和关系导航正确。
5. 图片真实显示，非图片系统打开；多选计数、同名分享、缺失实体提示、批量失败以及实际永久清理。
6. 云/LAN的离线修改、不同字段合并、同字段冲突、文件冲突、删除优先、断线补游标、后台断连和三次失败停止。
7. 同步显示绿色且仍有待下载的情况能明确解释；实际字节进度、成功时间和错误不造假。
8. 完整 FlyData 与备份对象仓库恢复，坏备份拒绝、恢复前保护、失败回滚，卸载不删业务数据。
9. 正式销售前验证价格/模块权限/三设备、真实支付、正确公钥、签名包、普通用户/干净电脑安装升级及售后。
10. 报告“编译通过、自动测试通过、截图检查、实机验收、已打包、已部署”分别是什么，不以其中一项替代全部。
