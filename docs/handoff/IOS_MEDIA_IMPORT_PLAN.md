# iOS 媒体导入兼容计划与查看建议

记录日期：2026-11-07。需求编号：FILE-24。**最新状态：用户已批准继续开发，iOS原生导入代码及图片/视频查看代码已写入；iOS尚待Mac/Xcode编译与iPhone实测。** 本文保留早期方案用于追溯，实际边界以[本轮实现记录](../release/media_viewers_20261107.md)为准。Android旧build50不包含新功能。

## 已确认需求

iOS版Fly从相册或文件导入图片、Live Photos和视频时，应自动生成适合Android和Windows10查看、播放的通用媒体文件。不能依赖接收设备另行安装专用格式扩展，也不能把修改文件扩展名当作格式转换。已经符合兼容要求的文件避免重复有损转换。

默认目标是照片JPG、需要透明通道的图片PNG、视频MP4。视频必须检查实际视频和音频编码，不是只检查MP4容器；建议兼容输出采用H.264视频与AAC音频。具体分辨率、帧率及编码参数须按支持的真实设备验收，不能承诺任意4K/HDR视频在所有设备播放。

Live Photo既有静态照片，也有动态视频。转换应保留可查看的静态内容与可播放的动态内容，不能无提示地只取一张静态图而丢弃动态部分。

这项能力应在iOS导入时完成，使后续本地同步和分享使用通用文件。**既有云同步仍只同步结构化数据，不因此开启图片或视频上传。** 原始相册素材或用户选择的源文件不能被覆盖、删除。

## 早期实现建议（以下不是全部已交付状态）

| 输入情况 | 建议处理 |
| --- | --- |
| HEIC/HEIF等静态照片 | 解码后输出高质量JPG；保留正确方向与合理色彩，不默认缩成缩略图 |
| 有透明通道的静态图片 | 输出PNG，避免转成JPG后丢失透明背景 |
| 已兼容的JPG/PNG | 直接导入；无需重复转码 |
| Live Photo | 生成一张JPG和一个MP4，并关联为同一媒体项目，界面不重复堆出两份无关文件；归组方式待设计 |
| MOV或使用HEVC等编码的视频 | 检查实际媒体轨道，按需要转换为MP4/H.264/AAC；已兼容的轨道可评估直接封装，避免不必要的重编码 |
| HDR、特殊色彩或高规格视频 | 为兼容副本评估SDR色调映射及适当的分辨率/帧率，保留源素材；参数与质量选项待真机验证 |

转换使用设备本地能力，界面保持可操作；提供进度、取消、失败原因与重试。只在完整输出成功后登记为可用文件并计算实际大小、摘要及缩略图，不能同步半成品。重复导入和重试不能悄悄产生多份文件或丢失Live Photo关联。大视频的耗时、发热、电量、磁盘空间和中断恢复需评估。

验收需要真实iPhone、Android和Windows10：普通照片、透明PNG、Live Photo、HEVC/MOV、MP4内仍是HEVC的视频、横竖方向、音画同步和HDR颜色；还要检查有限相册权限、需下载的云端相册素材、取消/失败/重试，以及本地同步后实际打开。Windows上的Flutter界面渲染不能代替这些验收。

## 开发前的软件事实（历史）

- 已有轻量内置图片查看：点击图片打开全屏查看，支持缩放与拖动。见`lib/features/files/presentation/image_file_viewer.dart`和`files_workspace.dart`的打开逻辑。
- 文件管理中的视频目前走系统默认应用，没有专用的内置视频播放界面。
- 上述事实不等于已支持HEIC、Live Photo或所有视频编码；本次没有新增媒体解码或格式转换。

## 开发前的产品建议（用户现已批准基础范围）

建议保留并完善内置图片查看，增加同目录上一张/下一张、手机左右滑动、双击缩放及分享入口，优先服务看产品图、现场图和客户资料的连续操作。旋转若后续加入，需区分临时查看和保存修改，不应误改原图。

建议后续增加轻量内置视频播放，首版只做播放/暂停、进度拖动、声音和全屏；离开页面停止播放并释放资源。保留“使用其他应用打开”作为兼容出口，不必一开始开发剪辑、滤镜、复杂字幕或完整影音资料库。

实施顺序建议为：先做iOS导入格式兼容，再完善图片连续浏览，最后加入基础视频播放。内置播放器不能代替格式转换；跨平台播放组件还需单独核对Windows、Android和iOS支持，不能假设手机插件直接覆盖Windows。具体组件及体积/维护成本待开发时评估，不在本次指定依赖。
