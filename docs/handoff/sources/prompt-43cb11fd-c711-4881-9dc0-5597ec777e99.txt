PART A — 客户列表“今日跟进”Checkbox 支持撤销
============================================================

当前：

Customer List 中点击客户前面的 Checkbox：

代表：

今天已经完成对该客户的跟进。

当前会：

- 创建 Follow-up Record
- 更新 lastFollowUpAt
- 根据 recurrence 更新 nextFollowUpDate
- 客户变灰/移动到底部等

这个业务逻辑保留。

但是现在增加：

# 再次点击 Checkbox = 撤销本次快速跟进。

------------------------------------------------------------
A1. 第一次点击
------------------------------------------------------------

例如：

Jack
今天需要跟进

用户点击：

☐ → ☑

执行：

1. 创建本次 Follow-up Record
2. 更新 Customer.lastFollowUpAt
3. 根据 recurrence 更新 nextFollowUpDate
4. 更新 Today List 状态

并显示轻量提示：

“已记录 Jack 的本次跟进”

不要弹 Dialog。

使用：

Snackbar / Toast / lightweight feedback。

显示约：

1.5~2.5秒。

------------------------------------------------------------
A2. 再次点击
------------------------------------------------------------

☑ → ☐

表示：

用户可能误操作。

撤销：

# 由这个 Quick Checkbox 创建的本次 Follow-up。

显示：

“已取消 Jack 的本次跟进”

------------------------------------------------------------
A3. 不要删除错误的 Follow-up
------------------------------------------------------------

不能：

简单删除 Customer 最新的 FollowUp。

因为最新 FollowUp：

可能是用户在 Follow-up Panel 手动录入的。

需要标记来源。

建议 CustomerFollowUp 增加：

origin

例如：

manual
quickTodayToggle

以及：

quickActionDate

例如：

2026-09-22

------------------------------------------------------------
A4. 撤销范围
------------------------------------------------------------

用户再次点击 Checkbox：

只撤销：

当前 Customer
+
当前 Follow-up Round / 当前日期
+
origin = quickTodayToggle

所创建的记录。

不要影响：

手动 Follow-up。

------------------------------------------------------------
A5. Follow-up 状态恢复
------------------------------------------------------------

第一次 Quick Follow-up 前：

记录必要 Previous State。

例如：

previousLastFollowUpAt
previousNextFollowUpDate

可以通过：

QuickFollowUpAction / Event

或者可逆状态保存。

撤销时：

恢复到操作前状态。

不要出现：

FollowUp删除了
但 nextFollowUpDate 仍然被推进一周

这种不一致。

------------------------------------------------------------
A6. 如果操作之后又产生其它跟进
------------------------------------------------------------

如果：

Quick Follow-up 以后，

用户又手动创建了新的 Follow-up，

不要直接破坏之后的数据。

需要安全判断。

如果无法安全自动恢复：

显示轻量提示：

“该客户已有新的跟进记录，请在跟进记录中修改。”

不要错误 rollback 后续记录。
