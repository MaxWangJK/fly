PART A — 财务信息微调
==================================================

一、汇率只保留两位小数

订单财务：

USD → RMB 汇率

UI 输入和显示都只保留：

2 位小数

例如：

7.1234

保存 / 展示：

7.12

推荐：

内部可以继续 Decimal / double

但 UI 和业务计算统一 round 到 2 decimals。

不要显示：

7.123456

--------------------------------------------------
二、汇率输入限制

输入允许：

7
7.1
7.12

最多两位小数。

例如：

7.123

用户输入后：

自动变：

7.12

或者阻止第三位小数。

保持 Desktop 输入自然。

--------------------------------------------------
三、收入 Summary 不显示 RMB 换算

当前页面：

已收合计
USD 1,000
折合 RMB 7,120

未收合计
USD 4,000
折合 RMB 28,480

这种展示需要修改。

要求：

# 收入区域只展示原始币种数据。

例如订单币种为 USD：

已收合计
USD 1,000

未收合计
USD 4,000

不要额外显示：

折合人民币
RMB equivalent

--------------------------------------------------
四、多币种收款

如果一个订单真的存在：

USD Payments
RMB Payments

则允许：

已收合计

USD 1,000
RMB 5,000

但：

不要再额外展示：

折合 RMB 总额

因为用户这里的需求是：

# 汇总显示原始记录数据即可。

--------------------------------------------------
五、未收合计

未收合计：

优先以：

订单销售币种

显示。

例如：

订单金额：
USD 5,000

已收：
USD 1,000

则：

未收合计：
USD 4,000

如果存在跨币种 Payment：

仍然可以内部使用汇率计算业务结果，

但当前 Summary UI 不展示额外 RMB 对应值。

如果算法存在歧义：

保持当前内部逻辑，
只简化 UI 展示。

--------------------------------------------------
六、成本合计同样简化

当前：

成本合计
RMB 50,000
折合 USD ...
或者：
USD ...
折合 RMB ...

改成：

# 只展示原始币种汇总。

例如：

成本合计

RMB 50,000

如果同时存在 USD 成本：

成本合计

RMB 50,000
USD 1,000

不显示换算后的第二层数字。

--------------------------------------------------
七、利润仍然统一 RMB

注意：

以上只是：

# Summary UI 简化

不是删除汇率和 RMB 利润计算。

最终：

预计利润

继续：

RMB xxx

因为利润需要统一核算币种。

--------------------------------------------------
八、财务内部模型保持

不要因为 UI 去掉 RMB 换算展示：

删除：

exchangeRate
currency
toRmb
profit calculation

这些仍然需要。

只是：

已收合计
未收合计
成本合计

UI 不显示额外换算值。

十八、恢复

--------------------------------------------------
十九、恢复前强制安全备份

先自动创建：

例如：

如果恢复失败：

可以回滚。

--------------------------------------------------
二十、恢复流程

1. validate package
2. verify database
3. close DB
4. backup current data
5. extract to temp
6. verify
7. replace business data
8. reopen DB
9. run migrations if necessary
10. refresh Riverpod state

--------------------------------------------------
二十一、版本兼容

Backup metadata：

必须记录：

schemaVersion
appVersion

如果备份来自：

更高版本 schema

当前版本无法恢复：

明确提示。

不要强行打开损坏 DB。

--------------------------------------------------
二十二、恢复必须安全失败

任何一步失败：

保持原数据。

不能出现：

旧数据已删
新数据恢复一半

这种情况。

使用：

temp directory
atomic replace

或安全 copy strategy。

--------------------------------------------------
二十三、用户数据不可静默覆盖

恢复前：

提示：

恢复备份将替换当前 Fly 数据。

当前数据会先自动备份。

[取消]
[继续恢复]

- 利润继续统一 RMB

Backup：

- 每日自动备份
- 7/30天保留
- 手动立即备份
- 一键恢复
- 恢复前自动备份当前数据
- 附件也恢复

Search：

- Enter 直接跳详情

Reminder：

- Customer / Task / Order

- 点击通知跳详情
