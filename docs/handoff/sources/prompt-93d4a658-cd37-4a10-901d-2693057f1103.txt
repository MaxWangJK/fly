# Fly V1 UI/UX 重构任务

当前 Fly V1 已经完成：

* Flutter 3.47.2
* Windows Build PASS
* Riverpod
* Drift
* SQLite
* Todo
* Task Detail
* Calendar Month View
* Eisenhower Matrix
* Release build
* Tests

现在不要继续增加功能。

## 本阶段唯一目标：

# 深度重构 Fly 的 UI 与交互体验

让它从“功能 Demo”变成：

# 一个真正好用、视觉舒服、交互快速的桌面任务管理工具。

任务管理软件 / 任务管理软件是重要参考对象。

注意：

不是复制 任务管理软件 源码、品牌、Logo、资源或像素级界面。

而是：

* 学习成熟交互
* 学习信息架构
* 学习尺寸比例
* 学习留白
* 学习状态反馈
* 学习任务完成后的视觉逻辑
* 学习快速新增任务的方法
* 学习桌面端三栏结构
* 学习 Calendar 与 Matrix 的信息密度

# 十一、任务完成行为必须重做

这是非常重要的 UX。

当用户点击：

```text
☑
```

任务完成以后：

不要立刻从页面消失。

而是：

# 1

Checkbox 进入 Completed 状态。

# 2

Title：

```text
中划线
```

例如：

```text
~~给 Jack 发报价~~
```

# 3

文字颜色变灰。

# 4

Task Row 背景可以轻微变灰。

# 5

该任务移动到：

# 当前任务列表最后面

例如原顺序：

```text
Task A
Task B
Task C
Task D
```

完成：

```text
Task B
```

变为：

```text
Task A
Task C
Task D

Task B ✓
```

不要删除。

不要隐藏。

除非用户设置：

```text
隐藏已完成
```

# 十四、新增 Task 必须极快

任务管理软件 好用的重要原因：

# 点击输入

# 输入内容

# Enter

就创建。

Fly 也必须如此。

顶部：

```text
+ 添加任务
```

点击后进入输入。

例如：

```text
┌───────────────────────────────┐
│ 输入任务内容...               │
└───────────────────────────────┘
```

输入：

```text
给 Jack 发报价
```

按：

```text
Enter
```

立即创建。

光标继续保留。

可以继续：

```text
跟进菲律宾客户
Enter
```

再次创建。

不要：

```text
输入
↓
点保存
↓
关闭窗口
```

这种低效率交互。
