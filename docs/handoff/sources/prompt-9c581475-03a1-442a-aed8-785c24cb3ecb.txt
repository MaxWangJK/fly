==================================================

一、核心协议

==================================================



Action Code：



1 = INSTALL



2 = OPEN



正式代码中可以使用：



AnalyticsAction.install = 1

AnalyticsAction.open = 2



但网络请求只发送数字：



1

2



不要发送：



install

open



这种字符串。



==================================================

二、设备标识

==================================================



第一次启动 Fly：



随机生成一个：



deviceCode



不要读取硬件机器码。



不要使用：



MAC

CPU ID

硬盘ID

IMEI

Windows MachineGuid



推荐生成：



12～16位随机 Base32 / Base62 字符串。



例如：



K7M4P9X2D6QF



要求：



- 随机

- 足够低碰撞

- 不包含容易混淆字符也可以

- 生成后永久保存在 Fly 本地配置中



例如：



analyticsDeviceCode



不要每次启动重新生成。



==================================================

三、第一次启动

==================================================



如果：



analyticsDeviceCode 不存在



则：



1. 生成 deviceCode

2. 本地保存

3. 上报 Action = 1

4. 同时上报 Action = 2



也就是说：



第一次运行：



/1

+

/2



因为：



这台设备既完成了安装，也属于当天活跃。



==================================================

四、以后启动

==================================================



以后每次启动 Fly：



检查：



lastAnalyticsOpenDate



如果：



lastAnalyticsOpenDate != 今天



则：



上报：



Action = 2



成功以后：



保存：



lastAnalyticsOpenDate = today



如果今天已经成功上报：



不重复请求。



==================================================

五、为什么一天只上报一次

==================================================



用户一天可能：



打开Fly 1次

打开Fly 20次



后台都应该认为：



今天这个设备活跃。



而不是：



启动20次。



所以：



客户端去重

+

服务端去重



双重保证。

十一、失败重试

==================================================

推荐：

可以再次尝试。

==================================================
