# ============================================================
# 0. 最重要原则
# ============================================================
#
# 不要将 Fly 改造成 Online-only 软件。
#
# Fly 2.0 必须继续：
#
# # Local First
#
# 即：
#
# 所有 Customer / Order / Task / Files / Notes 等操作
# 首先保存本机 SQLite。
#
# 即使：
#
# 没网
# Server Down
# VPN断开
#
# 用户仍然可以正常使用 Fly。
#
# 网络恢复后：
#
# 自动同步。
#
# ============================================================
# 1. 不要使用“最后修改时间直接覆盖”
# ============================================================
#
# 禁止实现：
#
# if remote.updatedAt > local.updatedAt:
#     overwrite local
#
# 因为：
#
# PC / Phone 系统时间不可靠。
#
# 两台设备时钟可能不同。
#
# Sync Conflict 不得依赖 Client Clock 判断。
#
# 使用：
#
# Stable UUID
# +
# Record Version
# +
# Server Change Sequence
# +
# Optimistic Concurrency
#

# 24. Idempotency
# ============================================================
#
# Server必须保存：
#
# mutationId。
#

#
# 不能重复执行。
#
# 网络重试：
#
# 必须安全。

# 25. Sync Push
# ============================================================
#
# POST:
#
# /api/sync/push
#
# 支持：
#
# batch mutations。
#
# 例如：
#
# 50~200条/Batch。
#
# ============================================================
# 26. Push Success
# ============================================================
#
# 如果：
#
# mutation.baseVersion
# ==
# server.version
#
# 则：
#
# apply
#
# server.version += 1
#
# generate change_seq。
#
# ============================================================
# 27. Conflict
# ============================================================
#
# 如果：
#
# baseVersion < server.version
#
# 表示：
#
# 其它Device已经修改过。
#
# 不要简单：
#
# client updatedAt 比较。
#
# ============================================================
# 28. Conflict Auto Merge
# ============================================================
#
# Mutation必须带：
#
# changedFields。
#
# Server检查：
#
# 从baseVersion之后，
# Server其它Mutation修改了哪些Fields。
#
# 如果：
#
# Device A修改：
#
# customer.phone
#
# Device B修改：
#
# customer.address
#
# 不冲突。
#
# 自动Merge。
#
# ============================================================
# 29. Same Field Conflict
# ============================================================
#
# 如果：
#
# Device A修改：
#
# customer.company
#
# Device B也修改：
#
# customer.company
#
# 才属于：
#
# Real Conflict。
#
# ============================================================
# 30. Same Field Conflict Rule
# ============================================================
#
# V2采用：
#
# Server Commit Order
#
# 作为最终Canonical状态。
#
# 即：
#
# 最后被Server成功接受的版本：
#
# 成为当前值。
#
# 但是：
#
# 绝不能静默丢掉另一份。
#
# 建立：
#
# sync_conflicts。
#
# 保存：
#
# local candidate
# server candidate
# entity
# field
# device
# time
#
# ============================================================
# 31. Conflict UI
