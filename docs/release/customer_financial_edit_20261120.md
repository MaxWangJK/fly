# 客户创建目录与订单财务附件修复

日期：2026-11-20。当前开发分支 `codex/fly-2-sync`。本轮修改源码，不新增安装包，最近成品仍为 Windows / Android **2.0.30+66**；以下修改不在 build66 中。

## 用户要求与实现

- 客户：从 B 级等二级目录新建后保留当前路由、级别和关联标签筛选，不再固定跳转全部客户。新建弹框沿用当前级别作为默认值；搜索文字会清空，以免刚创建的客户被旧搜索隐藏。
- 订单财务：收款、成本弹框中的“类型”改为“备注”，支持自由输入或留空。原有定金、尾款及成本快捷入口保留；历史文字与金额、币种、日期保留。
- 财务附件：编辑时载入已关联的文件名与图片缩略图，显示附件数量；支持一次多选、追加文件和桌面多文件拖入。每项都有移除按钮，移除旧附件后可添加新文件作为替换。
- 点击保存后才导入新文件并保存关联。取消不修改关联或复制文件。保存中禁止重复提交；失败保留表单并显示错误，同时尝试清理本次新导入文件，原附件保持。
- 移除取消这笔收款/成本与文件的关联，原文件仍保留在订单文件区，避免破坏其他记录可能使用的文件。需要删除文件本身时仍由订单文件管理完成。
- 附件内容尚未同步到本机时，文件记录仍保留，缩略图显示占位；打开沿用现有文件未下载提示，不会凭空丢弃关联。

## 数据与同步兼容

数据库仍为 schema20，后台仍为0005，无新依赖或新表。`OrderPayment` / `OrderCostEntry` 增加只读 `attachmentIds` 访问器；原 `attachment_id` 文本字段为空时表示无附件，单附件继续存原ID，多个附件存JSON字符串数组。编解码统一在 `FinancialAttachmentIds`，不是把JSON字符串当作文件ID查询。

现有单附件记录无需迁移，历史数据不改写。附件元数据仍使用现有 attachments；财务多附件关联通过现有增量同步字符串字段传输，文件仍经本地同步传输。查看本轮多附件记录的设备均应升级到包含本轮修改的客户端；旧版客户端只识别单ID，不应继续编辑多附件财务记录。

`FinancialAttachmentService` 先准备文件，再一次保存整笔财务记录的关联。中途失败会清理新文件及新增元数据；清理失败会记录诊断，返回原保存错误，避免掩盖问题。取消关联不会触碰原实体文件。
