# Fly 2.0.20+56 · 文件单击误触拖放修复

日期：2026-11-07。仅修复文件操作，沿用Windows交付范围；Android安装包仍为build50，iOS转换仍待Mac编译和iPhone验收。

## 原因与行为

文件卡片原先使用普通Pan手势启动Windows原生拖出，鼠标的默认判定只需约2个逻辑像素。隔离回归确认：按下、移动3×1像素、松开，本应打开PDF，却实际调用了系统drag。Windows平台消息若在松开之后到达，OLE会立即把文件落在鼠标所在位置；文件列表又无条件将收到的路径导入，因此触发真实的重复文件检查。

本轮改为鼠标主键明确移动超过8个逻辑像素才启动原生拖出。轻微移动仍走原有单击打开；右键和手机长按保持。Windows在进入OLE前再检查主键仍按下，已松开则取消。原生拖动期间暂停接收导入；即便回落事件稍晚到达，本机FlyData下的files/attachments托管实体也不会被拖放入口重新导入。其他外部文件照常导入，真正的内容重复仍由用户选择跳过、保留副本或替换。手动选择导入不受该路径保护影响。

查看器、菜单等路由盖住文件工作区时，后台DropTarget暂停；关闭后恢复。回归同时发现扁平文件夹遗漏了内部拖动的接收端，本轮补回：按住文件后拖到文件夹可移动，并用主题选中色提示目标。移动仍复用原有仓储验证，不复制或重排源文件；右键和批量移动继续保留。

## 文档查看建议（建议，不新增功能）

保持现有规则：图片、视频在Fly内快速查看；PDF、Word、Excel使用系统默认应用。当前不增加Office编辑器或完整PDF阅读器。更值得优先完善的是打开失败的明确原因、可选择其他应用、文件与客户/订单关联，以及外部修改后实体摘要与同步状态的一致性验证。

如以后用户频繁查看PI、提单或产品规格，可单独评估PDF首页缩略图、页数和轻量快看；不必同时引入批注、签名、编辑和复杂Office排版。Apple的[Quick Look](https://support.apple.com/guide/mac-help/preview-a-file-mchlgtd_prev01/mac)说明“快速看内容”和“打开完整应用”可以分工；这只是产品参考，不代表Fly已集成该能力。

## 后续开发建议（未承诺实施）

1. 发布前优先做真实三设备离线编辑、断网重连、文件可用状态、升级与备份恢复验收；已有功能的自动测试不能替代这些场景。
2. 在现有客户跟进和任务上，把下次联系、当天待办、客户上下文和完成后下一步衔接得更顺；先做少步骤、可追踪的每日工作流。[HubSpot的任务提醒与每日摘要](https://knowledge.hubspot.com/tasks/task-reminders-and-daily-digest)可参考，但不代表需接入该服务。
3. 围绕现有订单、收支和文件关联，集中呈现待收款、交期、待发货和缺资料的异常，减少遗漏；具体新增项需先核对现有模块，避免重复开发。
4. 完成Apple平台媒体兼容实机验收，评估视频封面和大文件空间提示。当前同步服务已有外部编辑后重算摘要、更新元数据及保留冲突副本的代码；应实测第三方应用的另存、替换文件及未保存情况，再优化变更检测开销，不重复开发已有逻辑。
5. 正式商业交付前验证邮箱、账号注销、设备授权、真实支付与升级。找回密码和注销云端账号已存在前后端代码，不能再列为“未开发”；修改已验证邮箱、支付和团队权限仍须分别评估。

产品主线建议聚焦“客户跟进→订单执行→资料归档→今日行动”。高级复盘、业务模板、托管云服务和将来的团队权限可形成付费价值；基础目录数量不宜作为首要收费门槛。这些仅为建议，不会自动变成待执行需求。
