# Fly 2.0.30+66：空闲维护和本地同步调度

2026-11-17，源码`3255fe1b01e76dcf4dbea23bec578a50edf8ac54`，分支`codex/fly-2-sync`。本次一并保存上一轮build65隐藏云同步/登录的工作区源码；build65当时以工作区快照构建，没有独立Git提交，不能将其快照ID当作提交。

## 原因与当前行为

build65虽然先显示主界面，但随即启动自动备份，库文件哈希和ZIP压缩仍在UI isolate上执行，因而可能在用户开始操作后卡住。现在可选维护至少等启动5分钟，且连续90秒没有键盘、鼠标、触屏或滚动操作才开始；活动会推迟任务，后台/隐藏时停止等待，返回前台重新等待空闲。匿名统计与自动更新检查同样延后，手动更新检查保持可用。提醒与用户主动同步不属于可延后的维护。

电脑自动备份使用独立isolate和独立SQLite连接，避免压缩、哈希占用UI计算及数据库快照排在UI连接的请求队列中；每日一次、保留周期和文件对象校验沿用原行为。恢复或迁移数据目录会等待已开始的备份结束。手机不启动自动备份，设置中的手机备份操作隐藏，保留本地同步把数据交给电脑备份。已经开始的工作线程不会因用户恢复操作而强制杀掉；磁盘I/O仍会占资源，不宣称物理设备零开销。

原电脑同步引擎每2秒请求本机localhost并执行文件检查，成功即被显示为设备已连接，即使并无外部设备。现在电脑启动仅监听配对和连接，无真实设备就没有同步引擎、数据轮询或文件扫描，界面显示“等待设备连接”。停止本地服务仍完全关闭监听。

新版设备通过已配对凭据建立局域网WebSocket，提供在线存在和变更提示。实际记录和文件继续使用原增量/分片协议；本地写入及对端变更提示合并250毫秒后触发同步，文件上传完成也发送提示，避免元数据先到、文件稍后到时等5分钟。心跳45秒只维持/检测连接，绝不启动业务同步或扫描；连接期间5分钟兜底补查。旧版无事件通道时兼容30秒轮询，旧客户端的认证请求使用90秒存在租约，两端更新才能获得完整事件调度。手机正常最小化或关闭时主动断开，异常断网由心跳超时识别；不宣称所有故障都瞬时识别。

最后一个设备断开后，电脑停止同步引擎、数据库写入监听、轮询及后续文件扫描，保留扫码监听。手机前台恢复可继续上次配对并补齐离线编辑。正在计算的一份文件摘要可以结束，但取消后不继续遍历下一文件或开始新的传输。断开时状态页不再定时读取文件库存；在线时最多每30秒刷新库存，记录成功时间和连接状态变化可即时刷新，传输字节进度继续使用事件。

界面仅显示本地同步和本地头像/名字；邮箱登录、注册、服务器设置和云同步切换入口继续隐藏。原云端账号/业务数据不注销、不删除。数据库schema20、后台迁移0005、依赖、SDK、原书籍密钥及两种安卓签名保持。
