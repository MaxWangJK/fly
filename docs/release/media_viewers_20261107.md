# Fly 2.0.19+55 · 媒体兼容导入、图片浏览与视频播放

开发日期：2026-11-07。按用户批准顺序实施：导入兼容、图片连续浏览、基础视频播放。当前主机为Windows，本轮Windows交付，Android安装包仍保留build50；不生成iOS安装包。

## 导入格式兼容

iOS新增本地媒体桥接，并注册进现有隐式Flutter引擎和Xcode编译文件列表。手机新增“照片与视频（保留Live动态）”入口，宽屏iOS导入同样可进入该入口；普通文件选择和拍照保留。PHPicker导出Live Photo照片与动态资源，普通导入仍可选文件。

实际图片类型由ImageIO检查。已经是JPEG/PNG的内容保留字节并使用正确扩展名；HEIC/HEIF等可解码静态图生成高质量JPG，带透明通道时生成PNG，渲染修正方向并采用标准色彩范围。视频检查实际轨道编码：兼容MP4/H.264/AAC直接使用，兼容MOV可重新封装为MP4；其他受支持输入使用H.264/AAC的1080p兼容预设，完成后再检查实际输出编码。HDR转SDR、音画同步、方向、质量及各机型仍须真机验收。

原相册与源文件不覆盖删除。转换异步执行，支持进度、取消、失败提示与重新导入；完成后才按实际输出计算摘要、大小并登记，临时输出按本次转换目录清理。取消不会把半成品入库。批次沿用逐文件提交和重复确认，已成功导入的文件不会因后续失败被回滚。

Live Photo本轮生成一张照片及一个同名带“(Live)”的视频，作为两个普通文件保存、移动、同步与分享，保留两类内容；合并为一张媒体卡片的归组界面尚未实现。中途失败会提示，可重新选择重试；重复确认按每个输出文件独立进行。

**iOS原生实现已写入，但当前主机无法运行Xcode或连接iPhone，本轮不能宣称iOS编译和真实转码已通过。** Windows/Android本轮不自动转换任意外部HEIC/HEVC文件；应由iOS导入端生成兼容副本再通过本地同步传输。现有特殊编码文件仍可能不被当前播放器支持，失败时保留其他应用打开入口。

Fly云同步仍仅同步结构化数据，没有新增媒体上传、服务器转码或云文件存储。

## 图片连续浏览

点击图片打开同目录图片集，按当前排序组织并从所选图片开始。普通资料按文件夹隔离；客户、订单等业务附件按所属记录隔离，避免串入其他客户或订单的图片。删除的文件和视频不进入图片集。

支持上一张/下一张、张数、键盘左右键、手机横向滑动、双击缩放、捏合及拖动。放大时滑动用于查看图片，切换按钮仍可用；切图重置缩放。支持分享和其他应用打开；未下载/损坏图片有占位提示，仍可切图或关闭。兼容原单图调用。

## 基础视频播放

视频直接打开内置播放器，默认暂停；支持播放/暂停、进度拖动、音量/静音、应用内全屏、分享和其他应用打开。桌面支持空格、左右快进/快退和Esc；退出全屏不重新创建媒体控制器。切到后台或失去活跃状态暂停，恢复前台不自动出声，关闭时释放播放器。失败提供重试和外部打开，初始化有超时，未下载文件提示错误。

播放使用固定版本`video_player 2.11.1`；Windows使用`fvp 0.39.1`和固定的MDK SDK0.39.0，提供硬件解码与软件解码后备。手机仍使用官方原生播放器。Windows真实验证曾发现系统Media Foundation实现不能播放标准示例，最终换为当前实现并重新验证；最终包不含原系统播放器插件。新增运行库增加安装包体积，换取更一致的本地播放。播放能力不代替iOS导入转换。

Windows CMake自动从官方固定发行地址获取SDK，校验SHA-256`68962cd889607417529f501c5ec169d07a87abdd7359c9ae9da7fd5689300a05`，不使用变化的nightly依赖。缓存位于忽略的build目录，新电脑需首次下载依赖。没有修改SDK缓存源代码或全局PATH。

SDK的FFmpeg动态库实际报告`git-2026-09-17-590fb40-avbuild`、LGPL2.1+，检查到GPL构建选项关闭。BSD/运行库来源、许可文本与固定SDK信息随[许可材料](../../assets/licenses/windows-media.txt)及安装包一起保存，应用许可列表也登记这些材料。媒体依赖是第三方运行库，与Fly账户和商业授权分开。
