## 用户场景与当前规则

工作电脑、工作手机、家庭电脑属于同一用户，三端各自离线新增客户或任务，再连接时应保留所有独立记录。同一条客户在家修改地址、公司修改电话，两字段分别融合；同一字段离线改了不同内容，自动按规则处理，不弹候选 A/B 要求用户选择。

设置现在提供本地同步与云同步；新安装默认本地，之后记住所选方式及是否启用。用户明确确认使用后台一次性设备接入码，以便邮箱注册登录开发前测试三端接入同一用户空间。

| 场景 | 使用方式 |
| --- | --- |
| 公司电脑与手机在可互通局域网 | 本地同步，手机扫描电脑二维码；业务数据和实体文件双向传输 |
| 工作电脑、手机、家庭电脑不在同一网络 | 三端选择云同步，接入同一用户空间；默认 `world-workshop.cn/api`，内部 HTTPS |
| 暂时没有云服务但希望在两台电脑转带记录 | 手机先后扫码配对两台电脑，前台在对应网络同步；保留两个协调者上下文，已有数据取并集 |
| 图片和文件内容 | 本轮云端对所有用户均不传实体；通过本地同步传输。云端仍可同步文件名、目录等记录信息 |

官网已搭建并不意味着 FastAPI 同步 API 已部署。本轮仅开发后台代码，提供与现有网站共存的 [Ubuntu 接入流程](../../server/deploy/cloud_sync_20261101.md)，没有改动或重新部署官网。

## 自动融合如何决定

- 保留稳定业务 ID，不拿客户名字或任务标题猜测是不是同一对象；独立创建的同名记录也保留，避免错误归并两个客户。
- 独立记录取并集，同一记录不冲突的字段合并。字段值不是按整条记录的 `updated_at` 或设备到达顺序覆盖。
- 明确基于已观察版本的操作优先；并发的同字段按携带的字段修改时间比较，相同时间按稳定 mutation ID 排序，结果可复现。新编辑在 SQLite 同一写入事务中捕获毫秒时间，原秒时间和已冻结请求仍兼容。
- 过大的未来时间被限制；已看到版本后的明确清空/修改仍能生效，即使设备时钟回拨。无法从两台错误时钟的离线设备推断绝对真实先后，采用固定规则并保存候选审计。
- 删除保留优先规则，旧离线修改不能复活；恢复必须基于当前墓碑的明确操作；永久文件墓碑不恢复。
- 重叠候选自动归档为已处理，原始内容保留在审计表，不再展示“保留 A/选择 B”的操作。附件二进制与笔记块的内容副本保护继续保留。
- 独立记录碰到数据库要求唯一的订单号、标签时，自动给后接收的独立记录追加短编号，保留 ID 及客户/任务关联；不把两笔订单或两个标签未经判断硬合成一条。
- 复盘答案按问题分别保留时钟，两端填写不同问题时合并，明确清空一个问题不删除其他答案。其他复杂 JSON/长文本仍以其持久字段为单位，并不声称理解文本语义或自动完成所有段落级编辑合并。

`fieldClocks` 跟随记录在云端和不同 LAN 协调者之间传递。手机切换工作电脑、家庭电脑时，分别保存版本、游标、待发队列和冻结重试；不因为重新绑定而把旧值都盖成“当前新编辑”。云用户/服务器绑定仍受保护，不能把其他用户的数据混入当前目录。

## 文件下载续传

本地下载新增受鉴权的 Range/If-Range 与强 ETag。`.part` 侧车绑定同步来源、记录、预期 SHA-256 和长度；中断或应用关闭后保留已下载字节，重开从偏移继续。已验证的同一 LAN 工作区改变 IP 时使用工作区身份作为恢复范围，不靠临时 IP 区分内容。

服务器返回 206 时检查起点、区间、长度及 ETag；旧服务器忽略 Range 返回 200 时从头写入，避免把完整文件追加到旧部分。内容版本变化、无效响应或最终校验失败会丢弃失效部分；只有完整长度和 SHA-256 匹配后，才将临时文件更名为正式文件。永久删除同时移除 `.part` 及侧车。上传保留已有分片/偏移续传。

实现：[下载接收](../../lib/features/sync/data/resumable_download.dart)、[HTTP/LAN 传输](../../lib/features/sync/data/cloud_sync_transport.dart)、[LAN Range 响应](../../lib/features/sync/services/lan_file_response.dart)、[文件同步](../../lib/features/sync/services/file_sync_service.dart)。协议语义参考 [RFC 9110 范围请求](https://www.rfc-editor.org/rfc/rfc9110.html#section-14)。

## 调度和重连

电脑的文件请求不再占用串行业务接收队列。文件 I/O 默认同时最多两个，同一上传哈希按序执行，最多接受 32 个在途/等待文件请求，超出返回稍后重试。业务修改先同步；持续传文件期间仍调度元数据增量交换，并以独立 in-flight 保护防止游标并发拉取。

手机记住最近最多五台明确扫码配对的电脑，安全存储设备秘密。先尝试上次地址；不可达时可通过 UDP 8766 发现已配对电脑的新地址。发现使用随机挑战与设备秘密派生的 HMAC 验证，之后再用正式令牌验证 HTTP 工作区；不会把附近任意电脑自动设为可信设备。UDP 受网络限制时保留旧地址、其他已配对电脑和重新扫码入口；没有无限子网扫描或公网穿透。

手机后台断开，前台恢复上次启用方式。自动重试仍在连续三次失败后停止，手动可再连接。LAN 当前仍为 HTTP，**本轮没有实现 LAN TLS**，也没有引入 LocalSend/Rust；发现验证不能替代链路加密。

已核对 Android 网络权限和 Apple 工程的本地网络说明/网络客户端与服务端配置，但未编译或运行 Apple 版本。iOS 的 UDP 广播还需要签名中的 multicast entitlement，当前未配置该受限能力，发现不可用时回退已有地址、扫码和云同步；不能声称 iOS 已验收自动广播发现。依据：[Apple 本地网络说明](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)。

实现：[文件调度](../../lib/features/sync/services/file_transfer_scheduler.dart)、[同步周期](../../lib/features/sync/services/sync_engine.dart)、[已配对设备发现](../../lib/features/sync/services/lan_discovery_service.dart)、[控制器](../../lib/features/sync/presentation/sync_controller.dart)。

## 临时设备身份与 Ubuntu 后台

公开接入接口为 `POST /api/sync/enroll-device`。管理员先创建一个用户空间，再在该空间为三台设备分别签发短期一次性码；API 根据码确定用户，拒绝客户端自行指定用户 ID。码哈希存储、一次消费，有速率限制；每台设备获得独立会话，支持令牌刷新、设备列表和撤销。注册/密码登录接口默认关闭，没有新增邮箱注册登录界面。

生产云部署同时在客户端和后台关闭文件内容，没有旧的特殊邮箱例外。为已有官网新增的 Compose 入口仅绑定回环端口 18766，Nginx 只并入 `/api/` 路由，保留原网站页面、证书与域名。没有取得或使用真实服务器凭据。

实现：[接入码签发](../../server/app/enrollment.py)、[管理 CLI](../../server/app/cli.py)、[API](../../server/app/main.py)、[迁移 0002](../../server/alembic/versions/0002_multi_device_sync.py)、[部署说明及操作命令](../../server/deploy/cloud_sync_20261101.md)。
