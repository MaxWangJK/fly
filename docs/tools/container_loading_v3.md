# 装柜 V3：空间拆分与排布

## 输入与兼容

取消安全间隙输入与计算。货物尺寸直接视为用户已含预留量的外包尺寸。旧数据库 clearance 字段保留以避免破坏旧数据，但不参与计算，新保存的方案写0；旧计算API的间隙参数只作兼容接收。

普通货物使用每排数量×纵向排数（高度方向的层数）=合计，推荐值放在始终可见的占位提示中。托盘和木箱仍为直接数量输入。保存的旧单一数量加载后分解为整数排布，保持原总数量，不擅自减少。

## 拆分规则

先摆放托盘/木箱，再按其横向占用区间与顶部高度建立互不重叠的长方体空间。单一堆叠底座靠边时一般为侧面+上方，居中时一般为左侧+上方+右侧。禁止堆叠的底座不提供上方空间。

每个空间显示编号、名称、长×宽×高，可独立选择货物和填写每排数量与层数。旧未指定空间的普通货物仍可自动分配到所有剩余空间。实际装载仍受空间、货物尺寸及全柜载重共同约束。

支持用户要求的2.9m纸箱放在2.8m托盘上方：仅在长度差不超过100mm时拓展规划空间，且可关闭“允许长度悬出≤100mm”。这不是结构安全结论；界面提示必须现场确认支撑、承重和固定条件。不自动允许更大悬出，不拓展宽度，也不突破箱体边界。

空间ID包含所属分节、底座及横向范围。底座改变使原空间失效时，保留原分配与数量并提示重新选择，不悄悄移动到其它空间。多底座复杂混装采用保守的横向分区，不承诺全局最优装载量。

## 显示

Flutter CustomPainter 绘制分节正面剖面：底座与空间编号不被前方货物遮挡。主3D视图在所有货物面之后叠加托盘/木箱的透视轮廓和名称，使居中、靠左时也可定位底座。透视轮廓是辅助显示，不改变真实几何或碰撞。

## 持久化决策

不改库结构、不删库。每个 Entry 的现有 JSON 快照新增版本键 layoutV3（perRow、rowCount、spaceId、allowOverhang）；货物快照解码仍保持兼容。关系、总数量和3D组继续使用原表。保存事务同时保存所有数据，测试覆盖恢复排布和空间关联。旧版应用不识别新增排布信息，不建议降级后覆盖保存V3方案。

## 回归基准

分节2900×2200×2690，两个2800×1200×1000托盘叠高2000，PVC纸箱2900×160×160：整节空柜容量208，放入托盘后为124。居中两侧各3×16=48，上方7×4=28；靠边侧面6×16=96，上方28。关闭悬出时，上方2900长货物不放入，总PVC96。
